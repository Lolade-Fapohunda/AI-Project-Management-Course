# User Story

## Purpose

A User Story describes a capability from the perspective of the person who needs it.

User Stories should explain **who** needs something, **what** they need, and **why** they need it.

## Definition Of Ready

Before development begins:

* [ ] User need is clear.
* [ ] Business value is clear.
* [ ] Acceptance criteria are defined.
* [ ] Dependencies are identified.
* [ ] Required information is available.
* [ ] Story is sufficiently understood by the team.

---

## Definition Of Done

Before the story is considered complete:

* [ ] Acceptance criteria are satisfied.
* [ ] Required testing is complete.
* [ ] Defects are resolved or formally accepted.
* [ ] Required documentation is complete.
* [ ] Business acceptance is obtained where required.
* [ ] Traceability is updated.

---

## PM Quality Check

* [ ] Story identifies a specific user/persona.
* [ ] Capability is clearly stated.
* [ ] Business value is clear.
* [ ] Acceptance criteria are measurable.
* [ ] Negative or edge cases are considered.
* [ ] Dependencies are identified.
* [ ] Story can be traced to a requirement or business objective.
