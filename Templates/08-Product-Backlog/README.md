# Product Backlog

## Purpose

The Product Backlog is the prioritized list of work required to deliver the product.

It provides the bridge between project requirements, Agile planning, releases, and development work.

## Prioritization

Use the MoSCoW framework:

* **Must Have** — required for the release.
* **Should Have** — important but not essential.
* **Could Have** — valuable if capacity permits.
* **Won't Have This Time** — intentionally excluded from the current release.

## Backlog Refinement

Before moving work into active development:

* [ ] Business value is understood.
* [ ] User need is clear.
* [ ] Acceptance criteria exist.
* [ ] Dependencies are identified.
* [ ] Priority is established.
* [ ] Story is sufficiently understood.
* [ ] Required data or inputs are available.

---

## PM Quality Check

* [ ] Backlog items trace to requirements or business objectives.
* [ ] Priorities are explicit.
* [ ] Dependencies are visible.
* [ ] Releases have defined objectives.
* [ ] Scope changes are controlled.
* [ ] Stories are ready before development.
* [ ] Completed work meets the Definition Of Done.
