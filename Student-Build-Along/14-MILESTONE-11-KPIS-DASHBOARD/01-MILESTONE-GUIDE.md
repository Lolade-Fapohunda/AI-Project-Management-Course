# Milestone 11 — KPI Dashboard & Monitoring

## PM Objective

Use product performance data to monitor an AI product, identify issues, and make informed Project Management (PM) decisions.

## What You Will Learn

By the end of this milestone, you will be able to:

* Define and interpret Key Performance Indicators (KPIs).
* Compare actual performance against targets.
* Identify improving and declining trends.
* Recognize threshold breaches.
* Determine when corrective action is required.
* Use dashboard evidence to support PM decisions.
* Explain how monitoring continues after product release.

---

# Part 1 — Everyone: KPI & Dashboard Analysis

KPI and dashboard management is part of the **core PM Track**.

All students complete this section.

You do **not** need to code to complete the PM analysis.

## Analyze the Dashboard

Using the provided dashboard/example:

1. Review each KPI.
2. Compare **Actual vs. Target**.
3. Identify improving or declining trends.
4. Identify threshold breaches.
5. Determine which issues require action.
6. Recommend corrective actions.
7. Document your PM decision.

Use the PM decision framework:

**KPI → Target → Actual → Trend → Threshold → Action**

## PM Deliverable

Complete the **KPI Dashboard Analysis**.

Your analysis should identify:

* KPIs meeting target
* KPIs missing target
* Improving trends
* Declining trends
* Threshold breaches
* Product risks
* Recommended actions
* Overall PM decision

# Part 2 — Optional Hands-On Dashboard Build

Students who choose the technical Build-Along will create a simple AI product KPI dashboard using Streamlit.

You will receive starter code and modify it step-by-step.

You are **not** being trained as a software engineer.

The purpose of this exercise is to understand how a PM can use technology to monitor product performance and support decision-making.

## Guided Build

### Step 1 — Review KPI Data

Review the provided KPI names, targets, and actual values.

Understand what each KPI measures and why the target matters.

### Step 2 — Create KPI Cards

Display the KPIs so a PM can quickly see current product performance.

### Step 3 — Add Target vs. Actual

Create a visual comparison between the target and current performance.

### Step 4 — Add a Trend

Display performance over time so the PM can identify improvement or decline.

### Step 5 — Add Status & Threshold Logic

Configure the dashboard to identify whether each KPI is:

* On Target
* Needs Attention
* Below Threshold

### Step 6 — Run the Dashboard

Launch the Streamlit application and review the dashboard.

### Step 7 — Interpret the Results

Identify:

* KPIs meeting target
* KPIs missing target
* Improving trends
* Declining trends
* Threshold breaches
* Business or product risks

### Step 8 — Make the PM Decision

Based on the dashboard, determine whether the product should:

**Continue → Improve → Escalate → Reassess**

Document the evidence supporting your decision.

# Monitoring After Release

KPI monitoring does not end when the product is deployed.

The PM should establish:

* KPI ownership
* Monitoring frequency
* Performance thresholds
* Alert conditions
* Review cadence
* Corrective-action process
* Escalation process
* Continuous-improvement process

The goal is to connect:

**Measurement → Insight → Decision → Action → Improvement**

# PM Checkpoint

Before completing this milestone, you should be able to answer:

> **What is the product telling us through its KPIs, and what should the PM do about it?**

## Technical Build-Along Checkpoint

Students completing the optional hands-on build should be able to demonstrate a functioning KPI dashboard that includes:

* KPI cards
* Target vs. Actual
* Trend information
* Status/threshold logic
* PM decision support

## Key Principle

A dashboard is not the PM decision.

The dashboard provides **evidence**.

The PM interprets the evidence, determines the business impact, and decides what action should happen next.
