# Milestone 12 — Capstone & Portfolio

## Objective

In this milestone, you will integrate the Project Management (PM) work completed throughout the course into a complete Artificial Intelligence (AI) project capstone and professional portfolio package.

You will demonstrate that you can manage an AI product through its lifecycle:

**Problem → Stakeholders → Requirements → Planning → AI Design → Data → Evaluation → Governance → Testing → Release → Monitoring → Continuous Improvement**

The goal is not simply to show that an AI application was built.

The goal is to demonstrate that you can:

**Define the problem → Make informed decisions → Manage risk → Evaluate evidence → Determine readiness → Measure outcomes → Recommend what happens next**

## MVP

The Minimum Viable Product (MVP) is the smallest useful version needed to provide core value and generate meaningful validation evidence.

## Release Scope

Release scope is the set of capabilities, controls, fixes, and approved changes included in a specific release.

**MVP is not automatically the same as release scope.**

A later release may contain capabilities that were not part of the original MVP.

# Part 8 — Release & Deployment

Review Milestone 10.

Keep the release and deployment decisions separate.

## Release Decision

Use:

**GO / CONDITIONAL GO / HOLD / NO-GO**

### GO

Proceed with release.

### CONDITIONAL GO

Proceed under clearly defined conditions with owners, validation requirements, and monitoring.

### HOLD

Do not proceed yet because required evidence, remediation, validation, or readiness work is incomplete.

### NO-GO

Do not release the current version.

## Deployment Decision

Use:

**DEPLOY / HOLD DEPLOYMENT / ROLLBACK**

A release decision does not automatically authorize deployment.

For example:

**Release: CONDITIONAL GO**

**Deployment: HOLD DEPLOYMENT**

is a valid outcome when production-specific conditions remain unresolved.

---

# Release Decision Authority

The PM provides the readiness assessment and recommendation.

The formally designated authority makes or confirms the release decision.

Possible decision authorities include:

* Product Owner.
* Executive Sponsor.
* Business Owner.
* Steering Committee.
* Release Board.
* Governance Authority.

Document:

**PM Recommendation → Authorized Decision → Conditions → Owner → Follow-Up**
